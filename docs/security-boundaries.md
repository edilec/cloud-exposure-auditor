# Security and evidence boundaries

An authorized local operator supplies exports from a stable input tree. Exports, manifests, normalized rows and source descriptions are untrusted data. They never authorize execution, network access, policy changes, or remediation. The product imports only standard-library file/path/crypto capabilities and the pure IP validator; no cloud SDK or transport call exists.

The assets protected are export bytes, private scope/resource identities, and host files outside the declared root. Reads resolve real roots/files, check component confinement and regular/opened-file identity, enforce post-open byte limits and refuse unstable files. Concurrent hostile ancestor replacement is outside portable Node guarantees; use a private stable export tree. No report-file mode or write/auto-fix capability exists.

The output boundary admits only frozen catalog text, integer counts, enums, and schema-controlled roles/pointers. No private path/name/account/key ID/hostname, input excerpt, digest, command, raw parser/OS error or stack reaches reports or diagnostics. Safe source roles map back to manifest descriptor ordinals and physical CSV record lines.

SHA-256 checks operator-supplied local source consistency, not authenticity. Normalization, effective provider controls and collection scope remain operator supplied. Missing pages/counts/regions/source classes, unsupported facts and limits result in incomplete, overriding known failures. Logging additionally needs actual supported region coverage, rather than an empty descriptor assertion. Pass covers only these five supported checks and is neither cloud-wide security nor compliance certification.

Tests deny network transports before product loading and use only synthetic local fixtures. No valid socket/listener/endpoint is used by denial controls. Mutation checks work in owned disposable copies and distinguish timeouts/infrastructure errors from assertion failures; documented enumeration is evidence, not a universal test-completeness claim.
